从零实现本地安全更新客户端。输入是自行合成的双镜像更新包，包含根信任文档、通道快照、目标清单和文件摘要，验证材料用绑定签名者代数与规范文档摘要的模拟验签记录。根信任为租户指定互斥的根、快照和目标角色以及阈值，角色按仓库标签和路径段授权。新根必须逐版递增，每一步同时由旧根和新根的不同持有人满足各自阈值，重复签名和同一持有人多个密钥只占一席，已吊销的签名代数不计。通道快照锁定确切目标清单摘要，单个目标还须在同一套已确认根下覆盖用途、通道、规范路径及文件摘要。

客户端对每租户固定已见根版本、通道版本、每个目标的版本下限和非递减可信时间。一个更新包可跨多个合法根中间版本并修改多个目标，任何一步无效都拒绝整包。拒绝减小任何版本下限，以及符合个别签名却来自互不匹配快照的混合内容；允许上游以更高版本重新发布已知旧内容，但必须有本次新签名。模拟文件只从本题目录读，客户端发布指针只指向已经验证且内容不可变的快照。

用 SQLite 支持并发更新与固定版本的只读查询。准备阶段可在事务外验证，发布前须在事务内重验根与通道的当前版本、时效和全部输入摘要，发布指针、版本下限、根信任与回执原子提交。旧根预检与另一写者先行换根、同版本不同镜像内容、历史快照文档与新清单混合、精确到期及多角色重复签名都要有独立预期。用同步点终止自己的测试进程于发布事务提交前和提交后未返回，再重启核对防回退水位、只读视图和请求重放。给出跨两次根轮换的完整正例与独立信任验证表，不接触真实软件仓库或服务。

在 Windows 原生 Python 3.12、标准库和 CPU 环境下实现，全部输入自行合成，离线测试。交付源码、README、可重放 cases.json 和自动化测试。提供 python -m solution --input cases.json --output result.json 与 python -m unittest discover -s tests -v。测试须断言具体结果，README 写明规则、输入输出、错误码和实测结果。
